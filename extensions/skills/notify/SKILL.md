# Notify — связь агента с внешним миром

Отправка писем (SMTP), сообщений в Telegram и в вебхуки (Slack/Discord/
Mattermost) одной командой, без зависимостей.

## Команда

В Docker-образе AgentHaus доступна глобальная команда **`notify`** (она в PATH):

```bash
notify --help
```

Если команды `notify` нет (другое окружение), используй скрипт напрямую —
его абсолютный путь:

```bash
python3 "${EXTENSIONS_REPO:-/opt/agent-canvas/extensions}/skills/notify/scripts/notify.py" --help
```

НЕ ищи скрипт по файловой системе (find/ls) и НЕ ищи его в рабочей
директории проекта — путь всегда один из двух выше.

## ГЛАВНОЕ ПРАВИЛО: это ПОЧТА АГЕНТА, владелец — получатель

Почтовый ящик, к которому подключён агент (`SMTP_USER` = `AGENT_PROFILE_EMAIL`),
принадлежит **агенту**, а не владельцу инстанса. Владелец **уже указал свои
контакты** в настройках (`.env` проекта): `NOTIFY_EMAIL_TO` (его email),
`TELEGRAM_CHAT_ID`, `NOTIFY_WEBHOOK_URL`.

Твоя роль: **веди переписку от имени агента** одинаково и никогда не говори,
что ящик — «почта владельца». Если владелец просит «зарегистрируйся на сайте» —
используй `AGENT_PROFILE_EMAIL`/`SMTP_USER` как адрес регистрации, имя и роль из
профиля (`notify profile`), а подтверждения читай из этого же ящика.

Поэтому:

- «отправь **мне** отчёт/письмо» → **сразу выполняй одну команду отправки**
  (`notify email`), получатель берётся из `NOTIFY_EMAIL_TO`. НЕ спрашивай
  адрес, НЕ проси подтвердить настройки SMTP, НЕ читай `.env`, НЕ запускай
  предварительно `status` — команда отправки сама проверит конфигурацию.
- «отправь письмо Иванову» / «отправь счёт клиенту» → тоже **действуй сразу**,
  адрес указывай явно (`--to`). Письмо уходит **от агента** (From/Reply-To =
  профиль агента), а не от владельца.
- «зарегистрируйся на сайте / создай аккаунт» → проверь профиль
  (`notify profile`), подставь `name/email/role` из него, после отправки формы
  **проверь почту** (`notify inbox --unseen` → `notify read`) и подтверди регистрацию.
- Спрашивай адрес только если просят отправить **другому** человеку и адрес
  не назван.
- `status` запускай только когда пользователь явно спрашивает, какие каналы
  настроены.

## Команды

```bash
# Профиль агента: как представляться (имя, email, роль, подпись). Смотри перед
# регистрацией на любом сайте, чтобы везде вводить ОДИНАКОВЫЕ данные.
notify profile
notify profile --json           # машиночитаемо (name/email/role/signature)

# Письмо владельцу (адрес берётся из NOTIFY_EMAIL_TO автоматически).
# Короткий текст — сразу через --body, без создания файлов:
notify email --subject "Тестовое письмо" --body "Проверка связи ✅"

# Отчёт: если отчёт уже есть в файле — отправь файл текстом и вложением:
notify email --subject "Отчёт: <краткая суть>" --body-file report.md --attach report.md

# Telegram владельцу
notify telegram --text "Задача выполнена ✅"

# Задать владельцу вопрос в Telegram и ДОЖДАТЬСЯ ответа (двусторонняя связь).
# Используй для подтверждения опасных действий и уточнений посреди задачи.
# Ответ печатается строкой «ОТВЕТ ВЛАДЕЛЬЦА: …»; exit code 3 = ответа нет
# (действуй по умолчанию и скажи об этом). Ответы принимаются ТОЛЬКО из
# чата владельца. Не запускай два ask параллельно (стоит lock).
notify ask --text "Деплоить на прод? (да/нет)" --timeout 900

# Slack/Discord-вебхук
notify webhook --text "Деплой завершён"

# Во все настроенные каналы сразу
notify send --subject "Отчёт" --body-file report.md

# Что настроено (секреты маскируются) — только по явной просьбе пользователя
notify status

# Помощник настройки Telegram: найти chat_id владельца (когда задан только
# TELEGRAM_BOT_TOKEN, а TELEGRAM_CHAT_ID ещё пуст). Сам диагностирует
# пустой getUpdates (нужно написать боту /start) и мешающий webhook.
notify chatid
```

## Переписка: приём и ответы на письма (IMAP)

Приём работает поверх тех же учётных данных, что и отправка: если задан
`SMTP_HOST` вида `smtp.<домен>`, IMAP-сервер выводится автоматически
(`imap.<домен>`, порт 993 SSL). Отдельные `IMAP_*`-переменные нужны только
если хосты нестандартные.

```bash
# Список последних писем (🆕 = непрочитанное)
notify inbox
notify inbox --unseen           # только непрочитанные
notify inbox --limit 30

# УМНАЯ загрузка (экономит токены и трафик) — фильтруй на сервере,
# не тяни весь ящик, если нужно конкретное письмо:
notify inbox --from ivanov@mail.ru          # от конкретного отправителя
notify inbox --from Иванов                  # по имени (кириллица тоже работает)
notify inbox --subject "счёт" --days 7      # тема + за последние 7 дней
notify inbox --since 01.08.2026 --before 15.08.2026   # период
notify inbox --unseen --subject отчёт       # фильтры комбинируются

# Прочитать письмо (выводит заголовки + текст; вложения можно сохранить)
notify read --uid 42
notify read --uid 42 --save-attachments ./attachments
notify read --uid 42 --max-chars 2000   # длинное письмо — читай сначала кратко

# Ответить отправителю (тема Re:, цепочка In-Reply-To/References сохраняется)
notify reply --uid 42 --body "Готово, отчёт во вложении." --attach report.md
```

Правило экономии: если пользователь называет отправителя/тему/период —
СРАЗУ передавай их фильтрами в `inbox`, а не листай весь ящик. Длинные
письма сначала читай с `--max-chars 2000`; полный текст — только если
нужно.

Сценарий «проверь почту и ответь»: `inbox --unseen` → `read --uid N` →
сделай, что просят в письме → `reply --uid N --body "…"`. Если пользователь
просит «следи за почтой» — предложи оформить это как автоматизацию
(cron-опрос `inbox --unseen`), а не бесконечный цикл в диалоге.

Явный получатель (если просили отправить не владельцу): `--to адрес` или
`--chat-id N`.

## Если отправка не удалась

- **exit code 2** (канал не настроен) — скажи пользователю один раз:
  «Заполни блок „Уведомления" в файле `.env` (см. `.env.example` и
  `docs/NOTIFICATIONS_RU.md`) и перезапусти контейнер». Не выдумывай данные
  и не проси пароли в чате.
- **exit code 1** — прочитай текст ошибки, там уже написано, что делать
  (см. таблицу диагностики ниже). Повторить отправку можно один раз.

## Как готовить отчёт

- Короткие сообщения и тестовые письма — сразу через `--body`/`--text`,
  промежуточные файлы не нужны.
- Длинный отчёт сохрани в `report.md` в рабочей директории и отправь через
  `--body-file report.md --attach report.md` — текст письма и вложение
  совпадают, отчёт остаётся в проекте.
- Тема письма — короткая и информативная: «Отчёт: анализ логов за 26.08».
- В Telegram длинный текст режется на части автоматически; файлы отправляй
  через `--attach` (уйдут документом).

## Регистрация на сайтах (аккаунты)

Когда владелец просит «зарегистрируйся на сайте», «создай аккаунт», «подпишись
на сервис»:

1. `notify profile` — узнай свои стабильные данные: `name`, `email`, `role`,
   `signature`. **Email для регистрации = `email` из профиля** (это почта
   агента), НЕ `NOTIFY_EMAIL_TO` и не личная почта владельца.
2. Заполняй **все формы одинаково**: имя — `name`, адрес — `email`,
   «кто вы»/«компания» — `role`. Никогда не меняй данные между сайтами, чтобы
   у агента было одно лицо.
3. После отправки формы проверь почту агента: `notify inbox --unseen` →
   `notify read --uid N`. Если письмо со ссылкой/кодом подтверждения — открой
   ссылку (при необходимости открой письмо, скопируй ссылку, перейди по ней
   браузерным инструментом) и заверши регистрацию.
4. Если сайт просит «имя/фио» и владелец не задал `AGENT_PROFILE_NAME` — бери
   дефолт «Агент AgentHaus», но сообщи владельцу, что для человеческого имени
   лучше заполнить `AGENT_PROFILE_NAME` в `.env`.
5. Не создавай аккаунт от имени владельца и не используй его личную почту без
   явной просьбы.

## Безопасность

- **Никогда не выводи** значения `SMTP_PASSWORD`, `TELEGRAM_BOT_TOKEN`,
  `NOTIFY_WEBHOOK_URL` в чат, логи или файлы. Скрипт сам маскирует их в
  ошибках — не обходи это.
- Не отправляй письма/сообщения на адреса, которые пользователь не называл и
  которых нет в настройках.
- Не рассылай массово: одно действие пользователя = одна отправка (плюс
  повтор при явной ошибке, максимум один).
- Вложения — только файлы, относящиеся к задаче; не прикладывай `.env`,
  ключи и другие секреты.

## Диагностика

| Симптом | Причина / что делать |
|---|---|
| exit code 2 | канал не настроен — попроси пользователя заполнить `.env` |
| `SMTP-аутентификация не прошла` | нужен «пароль приложения», а не обычный пароль (Gmail: myaccount.google.com/apppasswords; Yandex: id.yandex.ru → «Пароли приложений»; Mail.ru: account.mail.ru → «Пароли для внешних приложений») |
| Telegram `chat not found` | пользователь ещё не написал боту `/start`, либо неверный `TELEGRAM_CHAT_ID` — запусти `notify chatid` |
| Telegram `getUpdates` пуст (`result: []`) | боту ещё не писали, сообщение «сгорело» (>24 ч) или стоит webhook — `notify chatid` разберётся, webhook снимает `notify chatid --delete-webhook` |
| Telegram HTTP 429 | подожди `retry_after` секунд, повтори один раз |
| таймаут SMTP | проверь порт: 465 = SSL, 587 = STARTTLS (`SMTP_SECURITY`) |
| IMAP-аутентификация не прошла | тот же пароль приложения, что и для SMTP; проверь `IMAP_HOST` (например imap.timeweb.ru:993) |

Windows PowerShell: используй `python` вместо `python3`, флаги те же.
Подробная настройка каналов для пользователя: `docs/NOTIFICATIONS_RU.md`
в корне репозитория AgentHaus.
