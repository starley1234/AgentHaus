# Notify — связь агента с внешним миром

Навык позволяет отправлять письма (SMTP), сообщения в Telegram и в вебхуки
(Slack/Discord/Mattermost) одним скриптом без зависимостей:

```bash
python3 <путь-к-навыку>/scripts/notify.py --help
```

Windows PowerShell: используй `python` вместо `python3`, флаги те же.

## ГЛАВНОЕ ПРАВИЛО: не задавай лишних вопросов

Владелец инстанса **уже указал свои контакты** в настройках (`.env` проекта):

- `NOTIFY_EMAIL_TO` — его email;
- `TELEGRAM_CHAT_ID` — его Telegram;
- `NOTIFY_WEBHOOK_URL` — его канал Slack/Discord.

Поэтому когда пользователь говорит «отправь **мне** отчёт на почту» — НЕ
спрашивай адрес. Просто отправь на получателя по умолчанию. Спрашивать адрес
нужно только если пользователь явно просит отправить **другому** человеку.

## Порядок работы

1. **Проверь, что настроено** (быстро, без вывода секретов):
   ```bash
   python3 <путь-к-навыку>/scripts/notify.py status
   ```
2. **Если канал настроен — отправляй сразу**, без подтверждений:
   ```bash
   # Отчёт на почту владельца (адрес берётся из NOTIFY_EMAIL_TO автоматически)
   python3 <путь-к-навыку>/scripts/notify.py email \
     --subject "Отчёт: <краткая суть>" \
     --body-file report.md \
     --attach report.md

   # Короткое уведомление в Telegram владельца
   python3 <путь-к-навыку>/scripts/notify.py telegram --text "Задача выполнена ✅"

   # Сообщение в Slack/Discord-вебхук
   python3 <путь-к-навыку>/scripts/notify.py webhook --text "Деплой завершён"

   # Сразу во все настроенные каналы
   python3 <путь-к-навыку>/scripts/notify.py send --subject "Отчёт" --body-file report.md
   ```
3. **Если канал НЕ настроен** (`status` показывает «не настроен» или скрипт
   вышел с кодом 2) — не выдумывай данные и не проси пароли в чате. Скажи
   пользователю один раз: «Заполни блок „Уведомления" в файле `.env`
   (см. `.env.example` и `docs/NOTIFICATIONS_RU.md`) и перезапусти контейнер».

## Как готовить отчёт

- Сначала сохрани отчёт в файл (`report.md` в рабочей директории), затем
  отправь его через `--body-file report.md`. Так текст письма и вложение
  всегда совпадают, а отчёт остаётся в проекте.
- Тема письма — короткая и информативная: «Отчёт: анализ логов за 26.08».
- В Telegram длинный текст режется на части автоматически; файлы отправляй
  через `--attach` (уйдут документом).
- Явный получатель, если попросили отправить не владельцу: `--to адрес` или
  `--chat-id N`.

## Безопасность

- **Никогда не выводи** значения `SMTP_PASSWORD`, `TELEGRAM_BOT_TOKEN`,
  `NOTIFY_WEBHOOK_URL` в чат, логи или файлы. Скрипт сам маскирует их в
  ошибках — не обходи это.
- Не отправляй письма/сообщения на адреса, которые пользователь не называл и
  которых нет в настройках.
- Не рассылай массово: одно действие пользователя = одна отправка (плюс
  повтор при явной ошибке сети, максимум один).
- Вложения — только файлы, относящиеся к задаче; не прикладывай `.env`,
  ключи и другие секреты.

## Диагностика

| Симптом | Причина / что делать |
|---|---|
| exit code 2 | канал не настроен — попроси пользователя заполнить `.env` |
| `SMTP-аутентификация не прошла` | нужен «пароль приложения», а не обычный пароль (Gmail: myaccount.google.com/apppasswords; Yandex: id.yandex.ru → «Пароли приложений»; Mail.ru: account.mail.ru → «Пароли для внешних приложений») |
| Telegram `chat not found` | пользователь ещё не написал боту `/start`, либо неверный `TELEGRAM_CHAT_ID` |
| Telegram HTTP 429 | подожди `retry_after` секунд, повтори один раз |
| таймаут SMTP | проверь порт: 465 = SSL, 587 = STARTTLS (`SMTP_SECURITY`) |
