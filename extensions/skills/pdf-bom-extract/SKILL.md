Разбери PDF-спецификацию (BOM — Bill of Materials) в иерархический JSON,
обрабатывая PDF постранично через vision-модель.

## Когда использовать

- Пользователь прислал PDF (или сканы страниц) со спецификацией/ведомостью материалов.
- Нужна машиночитаемая структура: позиции, количества, обозначения, материалы.
- Модель сама не «видит» таблицы PDF, поэтому каждую страницу отдаём VLM.

## Рабочий процесс

1. **Найди PDF** в рабочей директории (это файл, загруженный пользователем;
   его имя обычно известно из контекста, `params.fileName`).
   ```bash
   ls -la .
   find . -maxdepth 2 -iname '*.pdf' -print
   ```

2. **Разбей PDF на страницы-картинки** (нужен `pdftoppm` из poppler-utils):
   ```bash
   # страницы в текущей папке: page-1.png, page-2.png, …
   pdftoppm -png -r 200 "ИМЯ.pdf" page
   ```
   Если `pdftoppm` нет — сообщи пользователю, что нужен poppler-utils.
   Если PDF уже сканом без текста — неважно: pdftoppm всё равно даст картинку.

3. **Каждую страницу отдай vision-модели** через инструмент
   `inspect_image_with_vision` с параметром **`path`** — ОДИН абсолютный путь к
   ТЕКУЩЕЙ странице (не передавай несколько картинок сразу — это сбивает
   модель). Чтобы сохранить нумерацию, включи в ВОПРОС краткий текстовый
   контекст — последние 5-10 уже извлечённых позиций (номер, обозначение,
   наименование):
   ```
   inspect_image_with_vision(path="/текущая/директория/page_-05.png",
     question="Извлеки из этой страницы позиции спецификации как JSON. Поля: "
     "designation(обозначение), name(наименование), quantity(количество), "
     "units(единицы), material(материал), note(примечание). Сохраняй "
     "вложенность сборок (sub_assemblies). Контекст предыдущих страниц "
     "(продолжай нумерацию): 1 Вал, 2 Корпус, ... Если таблицы позиций нет "
     "(титульник/рамка) — верни {\"items\":[]}. Верни ТОЛЬКО валидный JSON.")
   ```
   Профиль — первый доступный vision-capable (или укажи `profile_name`).
   Сохраняй `bom.json` инкрементально после каждой страницы, чтобы результат
   не терялся.

4. **Собери сквозной результат из ВСЕЙ спецификации**: объедини JSON-фрагменты
   всех страниц в ОДИН полный иерархический документ. Спецификации часто идут
   по разделам на разных страницах — склеивай по смыслу, сохраняя вложенность
   и продолжая нумерацию. В итоговый BOM должны попасть **все** позиции из всех
   страниц, а не только с последней.

5. **Отфильтруй мусор**: отбрасывай титульные/обложечные страницы, штампы,
   подписи, колонтитулы, «рамки», дубликаты разделов и служебные записи. Оставь
   только содержательные строки BOM. Если модель на странице вернула отказ
   («это не BOM») — пропусти страницу и иди дальше; не пиши её как пустую
   позицию.

6. **Запиши артефакты** в рабочую директорию:
   - `bom.json` — ПОЛНЫЙ иерархический JSON по всей спецификации (главный результат);
   - `bom.md` / `summary.md` — человекочитаемая сводка (таблицы по узлам)
     для сайта-просмотра сервиса.

## Обязательно: обработай ВСЕ страницы и не останавливайся рано

Это пошаговая задача — НЕ пытайся «рассуждать» про страницы, не посмотрев их,
и НЕ останавливайся, пока не пройдены ВСЕ страницы спецификации.

- **Сначала перечисли все страницы**: `ls -1 page_-*.png` и подсчитай их
  количество (например «53 страницы»). Запомни это число N.
- **Обрабатывай страницы ПОСЛЕДОВАТЕЛЬНО, по одной за раз** (`page_-01.png`,
  затем `page_-02.png`, …, до `page_-NN.png`). НЕ останавливайся после 2-3
  страниц «для проверки формата» — продолжай, пока не дойдёшь до последней.
- На каждой странице вызывай `inspect_image_with_vision` с **ОДНИМ `path`** —
  абсолютный путь к текущей странице (например
  `"/projects/bom-parse-<id>/page_-05.png"`), а в вопросе передавай текстовый
  контекст последних извлечённых позиций для продолжения нумерации. НЕ передавай
  несколько картинок сразу — это сбивает модель.
- Сохраняй `bom.json` ИНКРЕМЕНТАЛЬНО после каждой обработанной страницы
  (дописывай извлечённые позиции), чтобы результат не терялся даже если задача
  оборвётся.
- НЕ пиши «прогресс» вместо извлечения. Пока не вызван
  `inspect_image_with_vision` ни на одной странице — данные ещё не извлечены,
  продолжай.
- Если страница пустая/без таблиц (титульник/рамка) — добавь пустой фрагмент и
  иди дальше, НЕ прекращай обработку.

**Проверка полноты в конце (обязательна):**
- Пройдены ли ВСЕ страницы `page_-01.png` … `page_-NN.png`? Если нет — вернись
  и обработай пропущенные.
- `bom.json` должен содержать позиции со ВСЕХ содержательных страниц всей
  спецификации, а не только с первых.
- Оба файла — `bom.json` И `summary.md` — должны существовать в рабочей
  директории. Проверь: `ls -la bom.json summary.md`. Если `summary.md` нет —
  создай его.
- `bom.json` должен быть валидным JSON (`python3 -m json.tool bom.json`).

## Важно про качество

- Обрабатывай по ОДНОЙ странице с одним `path` (несколько картинок за раз
  сбивают модель и ведут к пустым `items: []`).
- Для сохранения нумерации включай в вопрос текстовое резюме последних позиций.
- Если модель вернула пустой `items: []` на содержательной странице — повтори
  вызов с более конкретным вопросом, не принимай пустоту сразу.

## Схема JSON (рекомендуемая)

```json
{
  "document": "название документа / чертежа",
  "assemblies": [
    {
      "id": "СБ-01",
      "name": "Сборка",
      "parts": [
        {"pos": 1, "designator": "Поз.1", "name": "Вал", "qty": 1, "unit": "шт", "material": "Сталь 40Х", "note": ""}
      ]
    }
  ],
  "notes": ["…"]
}
```
Поля настраивай под конкретную спецификацию; главное — сохранить иерархию и
числовые значения (количество/единицы) точно.

## Правила качества

- **Полнота**: в `bom.json` попадают позиции со ВСЕХ содержательных страниц всей
  спецификации (не только с последней). Пропускай титульники, штампы, рамки.
- Числовые значения (qty, количество) переноси **точно**, не округляй по памяти.
- Если значение нечитаемо — ставь `null` и отметь в `notes`.
- Не выдумывай позиции, которых нет на странице.
- Иерархия: если видишь «сборка → входит → …», отражай это вложенностью;
  используй контекст предыдущих страниц, чтобы не дублировать узлы.
- Дубли: если один и тот же узел/позиция встречается на нескольких страницах,
  объединяй (по обозначению), а не повторяй.
- В конце убедись, что `bom.json` — **валидный JSON** (`python3 -m json.tool`).
