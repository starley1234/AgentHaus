Организуй управляемую дискуссию нескольких агентов на заданную тему через
сервис **debate** (отдельная прослойка поверх единого бэкенда).

## Что делает сервис debate

- 2–3 агента (каждый — отдельный диалог/профиль на едином бэкенде) по очереди
  высказываются по теме.
- Проводится N раундов; между агентами передаётся только **скользящее окно**
  последних реплик (ограничение контекста), а старые раунды сворачиваются в
  **резюме** (режим суммаризации), чтобы контекст не раздувался.
- Опционально **арбитр** в конце даёт вердикт (ключевые аргументы, согласованные
  пункты, разногласия).
- Итог — **сайт-стенограмма** по HTTP.

## Как запустить

Сервис debate слушает на `http://localhost:8293`. Используй его REST API:

```bash
# запуск дискуссии
curl -X POST http://localhost:8293/api/run \
  -H 'Content-Type: application/json' \
  -d '{
    "topic": "польза и риски автономных агентов",
    "agents": [
      {"name": "writer"},
      {"name": "critic"}
    ],
    "rounds": 3,
    "window_size": 4,
    "summarize": true,
    "with_arbiter": true
  }'
```

Ответ: `{ "ok": true, "jobId": "<id>" }`.

Опрос статуса и результат:

```bash
curl "http://localhost:8293/api/status?id=<id>"   # running / finished / error
curl "http://localhost:8293/api/result?id=<id>"   # transcript, summary, arbiter, site_url
```

Стенограмма: открой `site_url` (например `http://localhost:8293/site/<id>/`).

## Параметры

| Поле | Описание |
| --- | --- |
| `topic` | тема дискуссии (обязательно) |
| `agents` | массив `{name, profile?}` — от 2 до 3 участников (name — шаблон: writer/critic/researcher/engineer; profile — имя агент-профиля, необязательно) |
| `rounds` | число раундов (по умолчанию 3) |
| `window_size` | сколько последних реплик передавать агенту (по умолчанию 4) |
| `summarize` | true — сворачивать старые раунды в резюме (по умолчанию true) |
| `with_arbiter` | true — добавить арбитра с вердиктом (по умолчанию false) |

## Правила

- Если сервис debate недоступен (порт 8293 не отвечает) — сообщи пользователю,
  что нужно запустить `services/debate` (и единый бэкенд), и дай инструкцию.
- Тему бери из запроса пользователя. Если пользователь не указал участников —
  предложи по умолчанию «Писатель» и «Критик» (или 2–3 уместных для темы).
- После запуска покажи пользователю ссылку на стенограмму, когда дискуссия
  завершится (опрос `/api/status` до статуса `finished`).
- Дай краткую сводку результата (summarized + вердикт арбитра, если был).
