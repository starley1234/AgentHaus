# Офисные файлы (Word / Excel / PowerPoint / PDF): как это устроено

Тебе часто нужны .docx/.xlsx/.pptx — разбор, что сделано, чтобы агент работал
с ними быстро и без лишних шагов.

## Проблема и решение

Раньше на каждую просьбу «сделай экселька» агент сначала выполнял
`pip install openpyxl …` — лишние 10–60 секунд, трафик и шанс упереться в
прокси. Теперь **библиотеки предустановлены в Docker-образ** (см.
`docker/Dockerfile`), а навык `office-files` сообщает агенту, что ставить
ничего не нужно, и даёт готовые рецепты.

## Что предустановлено

| Библиотека | Формат | Что умеет | Размер в образе |
|---|---|---|---|
| python-docx | Word .docx | создание, чтение, правка, таблицы, картинки | ~1 МБ |
| openpyxl | Excel .xlsx | чтение/запись, точечная правка с сохранением стилей | ~1 МБ |
| xlsxwriter | Excel .xlsx | быстрая запись, диаграммы, условное форматирование | ~1 МБ |
| python-pptx | PowerPoint .pptx | слайды, текст, картинки, таблицы | ~2 МБ |
| pandas | таблицы | read_excel/to_excel, CSV, аналитика | ~60 МБ (с numpy) |
| pypdf | PDF | объединение, разбиение, извлечение страниц | ~1 МБ |
| poppler-utils | PDF | `pdftotext` — текст из PDF (было и раньше) | системный пакет |

Итого ≈65 МБ к образу — почти всё это pandas/numpy, но именно они дают
«прочитай таблицу и посчитай» одной строкой.

## LibreOffice — сознательно опционален

Для двух задач нужен LibreOffice (headless):
1. конвертация документов в **PDF** (`soffice --convert-to pdf отчёт.docx`);
2. **legacy-форматы** .doc/.xls/.ppt (бинарные, до Office 2007).

Он добавляет ~700 МБ, поэтому по умолчанию выключен. Включение — одна команда:

```bash
docker compose build --build-arg WITH_LIBREOFFICE=1 && docker compose up -d
```

Если LibreOffice не установлен, а задача его требует, агент так и скажет —
одной фразой с этой командой.

## Обработка входящих файлов

Каналы, по которым файл попадает к агенту:

| Канал | Как работает |
|---|---|
| Вложение в диалог Canvas | файл сохраняется в рабочую директорию диалога — агент сразу его видит |
| Почта (IMAP) | `notify read --uid N --save-attachments ./attachments` — вложения письма складываются в папку |
| Папка проектов | всё, что положишь в `./projects/` на хосте, видно агенту в `/projects/` |
| Telegram (будущий bridge) | документы из чата будут скачиваться в рабочую директорию (уровень 2, см. TELEGRAM_TWO_WAY_RU.md) |

Обратно пользователю: файл остаётся в `./projects/...` **и** может быть
отправлен `notify email --attach файл.xlsx` / `notify telegram --attach файл.xlsx`.

Правила безопасности, зашитые в навык:
- входящий файл пользователя не перезаписывается — результат в новый файл;
- формат проверяется по содержимому (`file`), а не по расширению;
- кириллица: UTF-8, для CSV из старого Excel — `cp1251`.

## Типовые сценарии «одной фразой»

- «Прочитай вложение из последнего письма и сведи данные в Excel» →
  `notify inbox` → `read --save-attachments` → pandas → `notify reply --attach`.
- «Собери презентацию по этому отчёту» → python-pptx по данным из .md/.docx.
- «Заполни шаблон договора» → python-docx: открыть шаблон, заменить
  плейсхолдеры, сохранить новый .docx.
- «Сделай сводную таблицу из этих трёх CSV» → pandas + xlsxwriter с
  форматированием.

## Что потребуется для применения

Пересборка образа: `git pull && docker compose up -d --build`
(библиотеки и навык запекаются в образ).
