# Прохождение CAPTCHA в браузере: подход AgentHaus

Задача: когда сайт просит «докажи, что ты человек», агент должен уметь это
сделать **аккуратно** — как пользователь, который смотрит на экран, ведёт мышь
в нужную точку и кликает. Это не «обход» капчи скриптами, а легитимное
однократное действие (регистрация по просьбе владельца, вход, заполнение формы).

## Что уже было

`browser_use` в SDK AgentHaus умел:
- `browser_navigate` — открыть страницу;
- `browser_get_state` — «карта» интерактивных элементов по индексам;
- `browser_click <index>` — клик по элементу;
- `browser_type <index>` — ввод текста;
- `browser_scroll`, `browser_get_content`, управление вкладками и т.д.

Проблема для капчи: **капчи часто живут в `iframe`, рисуются картинками или
канвасом**, и у агента нет «индекса» для конкретной картинки. Нужно знать, куда
подвести и нажать мышью.

## Что добавлено

1. **Координаты в `browser_get_state`**.
   Для каждого интерактивного элемента теперь возвращаются:
   - `viewport_position` — прямоугольник в координатах видимой области;
   - `center_x` / `center_y` — центр (точка клика);
   - `absolute_position` — позиция относительно документа (для справки).

   Пример фрагмента:
   ```json
   {
     "index": 7,
     "tag": "img",
     "viewport_position": {"x": 120, "y": 340, "width": 80, "height": 80},
     "center_x": 160,
     "center_y": 380
   }
   ```

2. **`browser_move_mouse x y`** — подвести курсор в точку, не кликая.
   Пригождается для hover-эффектов, «человечной» траектории перед кликом и для
   того, чтобы попасть в зону, где капча активирует вторую часть проверки.

3. **`browser_click_coordinates x y`** — клик по координатам viewport.
   Используется для картинок-капч, областей внутри iframe и прочих элементов,
   у которых нет удобного индекса.

4. **Навык `web-captcha`** — единый сценарий для агента (типы капчи, порядок,
   лимиты, эскалация) и без-зависимая справка:
   `captcha_playbook.py --list`, `--self-check`, `recaptcha_image` и т.п.

## Логика прохождения (упрощённо)

```
browser_get_state --include_screenshot
   │
   ├── решается «само» (Turnstile)  → подождать 3–5 сек
   ├── есть вызываемый элемент      → browser_click <index>
   └── картинка/канвас/iframe       → по center_x/center_y:
                                        browser_move_mouse → browser_click_coordinates
   │
   └── появилась новая сетка/captcha → повторить, максимум 2–3 раза
         │
         └── не получается → остановиться и спросить владельца
```

## Выбор «мышка или индекс»

- Есть `index` из `browser_get_state` → лучше `browser_click`. Индексы стабильны и
  надёжны.
- Нет индекса, но есть координаты → `browser_move_mouse` + `browser_click_coordinates`.
- Капча в `iframe`: сначала попробовать обычный `browser_get_state` (он даёт и
  индекс iframe), затем, если карточки не появились, действовать по координатам.
- Обычную кнопку «Проверить» почти всегда можно кликнуть по индексу.

## Типы капчи и их особенности

| Тип | Что делать |
|---|---|
| reCAPTCHA checkbox | клик по галочке (index/центр), дождаться следующего шага |
| reCAPTCHA image (9 картинок) | прочитать задание, кликать нужные center_x/center_y |
| hCaptcha | кликать центры нужных объектов, подтвердить |
| Текстовая | распознать текст, ввести `browser_type`, подтвердить |
| Математическая | посчитать, ввести, подтвердить |
| Слайдер/пазл | честно сказать, что drag не поддерживается; VNC/человек |
| Cloudflare Turnstile | подождать и кликнуть везде, где появился кликабельный виджет |
| Неопределённая | 1 аккуратный шаг → эскалация |

## Чего НЕ делаем

- Не рандомим клики сотнями — это похоже на бота и часто усиливает анти-бот.
- Не используем сторонние «решатели капчи» для массового обхода: нарушает ToS,
  может привести к блокировке и не относится к задаче агента.
- Не проходим капчу в потоках, связанных с платежами/законными ограничениями,
  без явной просьбы владельца.
- Не считаем задачу решённой без подтверждения (новая страница, «спасибо»,
  успешное состояние).

## Как женщина/человек попадает в процесс

Если капча зацикливается (3+ раза) или нужен drag/условие, которое агент не
должен решать сам; можно:
- включить `OH_ENABLE_VNC=true` (уже есть в docker-compose) и пройти капчу вручную
  во вкладке «Browser»;
- попросить владельца прислать код/ссылку (например, из email) и продолжить;
- использовать официальные API/вход вместо капчи, если сайт их предлагает.

## Как включить

1. Пересобрать образ: `docker compose up -d --build`.
2. Убедиться, что браузерный тулсет доступен (Chromium в образе есть по штатной
   настройке).
3. Навык `web-captcha` подхватывается автоматически из
   `extensions/marketplaces/openhands-extensions.json`.

Связанные файлы:
- `extensions/skills/web-captcha/SKILL.md` — инструкция для агента;
- `extensions/skills/web-captcha/README.md` — краткое описание;
- `extensions/skills/web-captcha/scripts/captcha_playbook.py` — CLI-справка.
