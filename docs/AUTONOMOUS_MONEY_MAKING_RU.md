# Как AgentHaus может сам зарабатывать деньги — идеи с минимальным участием

Ты правильно уточнил: не монетизация приложения (продажа лицензий), а использование AgentHaus как **автономного завода**, который сам производит коммерчески ценный продукт и продаёт, а ты только снимаешь сливки.

AgentHaus уже умеет то, что другие не умеют: запускать **несколько агентов параллельно** (debate), делать **vision-цикл** (фото → OpenSCAD → рендер → сравнение → правка), парсить PDF через vision (BOM), писать книги и документацию как сайт, работать полностью оффлайн с локальными LLM. Это и есть основа для "денежных" сервисов.

Ниже — 5 проверенных направлений с минимальным участием, что уже есть в `services/` и что надо доработать.

---

## Принцип: от "чат с агентом" к "сервис-прослойка"

В `services/` уже есть паттерн, который отличается от примитивного "конвейера контекста":

- **Единый бэкенд** (agent-server :18000) — один на всех
- **Прослойка `server.mjs`** — тонкий Node.js сервис на своём порту (8290-8300), который создаёт диалог через REST (`POST /api/conversations`), опрашивает статус, собирает результат в сайт/JSON/API
- **Шлюз `gateway.mjs`** на :8290 — витрина всех сервисов, с админкой `/admin/` (access: public/registered/admin), hot mount без перезапуска

То есть ты можешь добавить папку `services/my-money-maker/` с `config.json` + `server.mjs` — и она появится в витрине, с биллингом, без изменения ядра SDK.

Это и есть ключ к автономному заработку: **сервис сам принимает заказ (файл, тема, URL), сам делает работу через агента, сам публикует результат и сам продаёт**.

## Направление 1: BOM-парсер как API для производства (самый быстрый к деньгам)

**Что уже есть:** `services/bom-parse/` — разбирает PDF со спецификацией (ведомость материалов) постранично через vision-модель в иерархический JSON + сводку. В `extensions/skills/pdf-bom-extract/` уже есть навык с `inspect_image_with_vision`.

**Коммерческая ценность:**
- Заводы, КБ, отделы закупок получают PDF-спецификации от поставщиков (100-500 страниц, таблицы, чертежи). Ручной перенос в Excel/ERP — 2-5 часов на документ, €50-100.
- Твой API: загрузил PDF → получил JSON с позициями, количеством, материалами, иерархией.
- Рынок: EU производство (DE — Mittelstand), 3D-печать, электроника. В DE компании платят за обработку BOM без отправки в US облако (GDPR).

**Как работает автономно:**
- Клиент загружает PDF на `bom-parse` сервис (порт 8290/bom-parse/)
- Прослойка разбивает PDF на страницы-картинки через `pdftoppm` (уже в Dockerfile есть `poppler-utils`)
- Для каждой страницы вызывает агента с навыком `pdf-bom-extract` (vision), который извлекает таблицу
- Собирает иерархический JSON, делает сводку, публикует по `/out/`

**Что доработать для денег (2-3 дня):**
1. Добавить в `services/bom-parse/server.mjs`:
   - Приём файла через `POST /api/run` (multipart), а не только путь
   - Stripe webhook: `POST /api/run` требует `x-api-key` с балансом, списывает €0.20 per page
   - Сохранение результата в `out/<jobId>/bom.json` + `summary.md` + `out/index.html` с таблицей
   - Экспорт в Excel/CSV (`json -> xlsx` через `exceljs`)
2. Добавить лендинг с примером: "Загрузите PDF, получите Excel за 2 минуты"
3. Добавить админку для просмотра заказов

**Монетизация:** €0.20/page, средний BOM 50 pages = €10 per doc. 10 docs/day = €100/day = €3000/month с минимальным участием (только поддержка).

**Где брать клиентов:** Upwork "BOM extraction", LinkedIn procurement managers в DE, Etsy 3D-print sellers who need BOM.

## Направление 2: Vision → OpenSCAD → 3D-модель для Etsy / Cults3D

**Что уже есть:** `services/nq9n-vision-to-openscad/` — фото → OpenSCAD → рендер → vision-сравнение → правка до 15 итераций. Навык `openscad` с `openscad_render_png_url` + `file_editor view` для бок-о-бок сравнения.

**Коммерческая ценность:**
- На Etsy, Cults3D, MyMiniFactory продаются кастомные 3D-модели (вазы, подставки, cookie cutters) по €3-10. Тренды меняются быстро, ручное моделирование — долго.
- Твой завод: берёт трендовое изображение (например, "cat vase" с Pinterest), генерирует параметрическую OpenSCAD модель, рендерит, публикует на маркетплейсе.

**Как работает автономно:**
- Крон-автоматизация `research-brief-writer` ищет тренды "trending 3d printable vase" через Tavily
- Для каждого тренда вызывает `nq9n-vision-to-openscad` сервис: скачивает изображение в `target.png`, запускает vision-цикл, получает `detail.scad` + `render-*.png`
- Публикует на Cults3D через их API или готовит Etsy listing draft (фото + описание + scad)

**Что доработать (3-5 дней):**
1. В `services/nq9n-vision-to-openscad/` добавить:
   - Вход: URL изображения или поиск по ключевым словам
   - Выход: `detail.scad`, `render.png`, `metadata.json` с размерами, параметрами
   - Экспорт в STL через `openscad -o model.stl detail.scad` (добавить openscad в Dockerfile)
   - Генерация описания для Etsy через `frontend-design` навык
2. Добавить сервис `services/etsy-publisher/` который берёт готовые модели и через Etsy API создаёт черновик листинга
3. Добавить Stripe для продажи напрямую: сайт-витрина на 8290 с галереей моделей, кнопка "Купить STL за €5"

**Монетизация:** 1 модель в день * €5 * 30 = €150/month с одной площадки, но если 10 моделей в день и 3 площадки — €1500/month. Участие — только одобрение трендов раз в неделю.

## Направление 3: Авто-генерация нишевых сайтов с аффилиаткой (SEO-ферма)

**Что уже есть:** `services/book-site/` (тема → книга по главам → статический сайт на 8290) и `services/docs-site/` (папка репо → документация → сайт на 8291). Навыки `frontend-design`, `theme-factory`, `research-brief`.

**Коммерческая ценность:**
- Нишевые сайты "Best X for Y" с аффилиатскими ссылками Amazon, Aviasales, Booking приносят €100-1000/month на пассиве, если есть SEO-трафик.
- Твой завод: каждый день генерирует новый сайт на микро-нишу (например, "Best 3D printer for miniatures 2026", "Best dog food for German Shepherd"), с исследованием через Tavily, дизайном через frontend-design, публикацией на Vercel/Netlify.

**Как работает автономно:**
- Автоматизация `research-brief-writer` (cron) получает тему из списка ниш (CSV)
- Создаёт диалог с промптом "Напиши книгу/гайд по теме X, с сравнением продуктов, плюсы/минусы, с аффилиатскими ссылками"
- Агент пишет главы в `chapter-*.md`, прослойка собирает в статический сайт с шаблоном, вставляет аффилиатские ID
- Публикует на поддомен `x.agenthaus.local` или на Vercel через их API

**Что доработать (5-7 дней):**
1. Новый сервис `services/seo-affiliate-site/`:
   - Конфиг: список ниш, аффилиатские ID, шаблон сайта, SEO-мета
   - `POST /api/run` с `{ niche: "best 3d printer for miniatures" }` → jobId
   - Агент использует `research-brief` + `frontend-design` + `evidence-based-citations` для достоверности
   - Результат: `out/<jobId>/index.html` с таблицей сравнения, кнопками "Buy on Amazon", Schema.org разметкой
   - Авто-публикация через `vercel` навык
2. Добавить проверку уникальности и анти-плагиат через `evidence-based-citations`
3. Добавить Stripe для продажи готовых сайтов: "Купить готовый аффилиатский сайт за €199"

**Монетизация:** 1 сайт в день, 10% начинают приносить €50/month через 3 месяца → 30 сайтов * €50 = €1500/month пассива. Продажа сайтов как продукта — €199 * 5/month = €1000. Итого €2500/month.

## Направление 4: Meeting Notes SaaS для команд (B2B, самый стабильный)

**Что уже есть:** `services/meeting-notes/` — текст стенограммы → структурированный конспект (решения, задачи, вопросы, резюме) → страница на 8292.

**Коммерческая ценность:**
- Команды в Zoom, Google Meet тратят время на ручные конспекты. Otter.ai, Fireflies берут $20/user/month.
- Твой self-hosted вариант для EU компаний, которые не хотят отправлять стенограммы в US (GDPR), с русской локализацией.

**Как работает автономно:**
- Клиент загружает .txt/.srt стенограммы (из Whisper, Zoom)
- Агент с промптом из `config.json` разбирает на `notes/*.md`: Summary, Decisions, Action Items (с ответственными), Questions
- Публикует страницу, отправляет в Slack/Notion через интеграции (уже есть `slack`, `notion` в integrations catalog)

**Что доработать для SaaS (1 неделя):**
1. В `services/meeting-notes/` добавить:
   - Приём аудио-файла, транскрибация через Whisper локально (добавить whisper в Dockerfile) или через `elevenlabs` интеграцию
   - Интеграция с `slack-channel-monitor` автоматизацией: слушает канал #meetings, при новом сообщении с транскриптом — авто-конспект и пост в Notion
   - Stripe: €19/month per team, 100 meetings
   - Пользователи: таблица в SQLite `users`, `teams`, `meetings`
   - Экспорт в Notion, Linear, Jira через существующие интеграции
2. Лендинг: "GDPR meeting notes, self-hosted, €19"

**Монетизация:** 20 команд * €19 = €380 MRR, стабильный, низний churn, минимальное участие (поддержка).

## Направление 5: Docs-as-a-Service для open-source (авто-документация)

**Что уже есть:** `services/docs-site/` — путь к папке репо → агент читает README/код/примеры → пишет разделы `docs/*.md` → сайт на 8291.

**Коммерческая ценность:**
- 80% GitHub репо без нормальной документации. Мейнтейнеры хотят доки, но нет времени.
- Твой сервис: вставляешь URL GitHub репо → получаешь готовый сайт документации с поиском, примерами, API reference.

**Как работает автономно:**
- GitHub App слушает новые репо или PR, при создании вызывает docs-site сервис
- Агент использует `code-review`, `technical-writing`, `frontend-design` навыки
- Результат — статический сайт, PR с доками в репо

**Что доработать (1 неделя):**
1. В `services/docs-site/` добавить:
   - Вход: GitHub URL, клонирование репо
   - Генерация через `setup-agents-md` + `technical-writing` + `theme-factory`
   - Публикация на GitHub Pages через `gh` CLI
   - Stripe: €9 per repo, €49/month unlimited
2. Добавить GitHub Marketplace App для одного клика

**Монетизация:** 50 репо * €9 = €450 one-time + 10 подписок * €49 = €490 MRR.

## Что надо доработать в ядре AgentHaus для всех направлений

### Для автономности (чтобы участие минимально)

1. **Биллинг в gateway.mjs:**
   - Сейчас gateway только маршрутизирует. Добавить middleware для проверки `x-api-key` с балансом из SQLite (`users` таблица с `credits`)
   - Stripe webhook для пополнения
   - Rate limiting по IP и по ключу

2. **Админка `/admin/` уже есть, но нет UI логина:**
   - Добавить RBAC из `lib/auth.mjs` (users/roles/users_roles) с UI
   - Добавить страницу "Заказы" / "Jobs" с статусом, логами, результатом

3. **Хранилище результатов:**
   - Сейчас `out/` папка внутри сервиса. Для прода нужно S3 или `LOCAL_STORAGE_PATH` + публичный URL
   - Добавить `FILE_STORE=s3` поддержку с MinIO для self-hosted

4. **Очередь задач:**
   - Сейчас каждый `POST /api/run` запускает агента сразу. При 10 заказах — 10 параллельных агентов, может упасть
   - Добавить BullMQ или простую очередь в SQLite с лимитом concurrency

5. **Мониторинг и алерты:**
   - Добавить в `gateway.mjs` `/health` который проверяет все сервисы
   - Telegram бот для алертов: "Job <id> упал", "Баланс Stripe пополнен"

### Для качества (чтобы продукт покупали)

6. **Vision-модели:**
   - Gemma-3 уже распознаётся как vision автоматически, но для BOM нужен более точный
   - Добавить поддержку Qwen-VL, LLaVA через `OPENHANDS_VISION_MODELS` и бенчмарк

7. **OpenSCAD рендер:**
   - В Dockerfile добавить `openscad` и `xvfb` для рендера без дисплея
   - Добавить `openscad -o model.stl` для экспорта STL

8. **PDF обработка:**
   - `poppler-utils` уже есть, но нужен `pdftoppm -png -r 300` для высокого качества страниц

9. **Лендинги для каждого сервиса:**
   - Сейчас у каждого сервиса простой HTML. Сделать через `frontend-design` навык красивые лендинги с примерами, ценами, кнопкой Stripe

### Для масштаба

10. **Маркетплейс сервисов:**
    - Сейчас сервисы — папки. Сделать `services/registry.json` с метаданными (title, description, price, icon)
    - Gateway читает registry и показывает витрину с ценами и кнопкой "Попробовать"

11. **API документация:**
    - Добавить OpenAPI для каждого сервиса, Swagger UI в gateway

## Почему не примитивные идеи

Примитивные типа "конвейер контекста" — это когда ты просто передаёшь текст от одного агента к другому без добавленной стоимости. Здесь ценность в **специализированных навыках + vision + публикация как продукт**:

- BOM — не просто OCR, а иерархический JSON с пониманием таблиц, чертежей, через vision
- OpenSCAD — не просто генерация кода, а цикл рендер → сравнение → правка, который даёт точную модель
- Book-site — не просто текст, а готовый сайт с дизайном, который можно сразу продавать
- Meeting-notes — не просто суммаризация, а структурированный конспект с задачами и интеграцией в Slack/Notion

Каждый сервис производит **готовый к продаже артефакт** (Excel, STL, сайт, конспект), а не промежуточный текст.

## Итог

AgentHaus может зарабатывать сам, если превратить его из "чата с агентом" в **завод сервисов-прослоек**, каждый из которых решает узкую, но дорогую задачу (BOM, 3D, доки, конспекты, SEO-сайты) и продаётся через Stripe с минимальным участием.

Начни с BOM (быстрые деньги) → добавь Meeting Notes SaaS (MRR) → затем SEO-ферму и 3D-маркетплейс (пассив).

Доработки ядра — биллинг в gateway, очередь, S3, админка с заказами — займут 1-2 недели, но дадут автономность.
