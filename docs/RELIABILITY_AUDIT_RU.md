# Аудит производительности и надёжности AgentHaus

Дата: 2026-08-23

## Что проверено

- Стек запускает агент-сервер, automation и статический ingress в одном контейнере; ключи сессии и шифрования генерируются один раз и сохраняются в постоянном томе.
- У агент-сервера уже есть контроль времени команд, изоляция активных диалогов, восстановление после прерванных запусков и выгрузка неактивных диалогов из памяти через 20 минут. Это снижает риск зависших задач и накопления памяти.
- Endpoint `GET /api/file/archive` строит архив потоково на диске, не следует симлинкам и удаляет временный файл после отправки. Он подходит для скачивания рабочих файлов без загрузки их целиком в RAM.
- Файловая вкладка уже ограничивает отрисовку 2 000 путями и исключает типичные тяжёлые каталоги при просмотре, поэтому большой репозиторий не должен зависать только из-за открытия списка файлов.

## Исправления в этой ветке

1. **Экспорт рабочей области.** Во вкладке «Файлы» добавлена кнопка со стрелкой скачивания. Она создаёт и скачивает один `zip` со всеми файлами активной рабочей области. Запрос идёт с ключом текущего диалога; для cloud-backend используется штатный proxy. Создание архива выполняется потоково на сервере, а кнопка блокируется до окончания одного запроса — параллельные тяжёлые архивирования не запускаются.
2. **Контроль параллелизма.** В Docker Compose добавлен `OH_MAX_CONCURRENT_RUNS=4`. Ранее использовался внутренний дефолт SDK `10`, что для одного self-hosted узла могло одновременно занять десять потоков, браузеров и запросов к LLM. Значение можно осознанно увеличить в `.env` при достаточных CPU/RAM и квотах LLM.
3. **Устранение утечки памяти шлюза сервисов.** Обновление сервиса в `services/gateway.mjs` раньше импортировало ESM-модуль с `Date.now()` в URL. Node сохраняет каждый такой URL в module cache, поэтому повторные refresh из админки неограниченно накапливали графы модулей. Теперь URL версионируется `mtime + size`: файл всё ещё подхватывается после изменения, а неизменённый сервис использует один кэшированный модуль.

## Практические рекомендации

- Оставляйте `OH_MAX_CONCURRENT_RUNS=4` для машины с 4–8 vCPU. Повышайте постепенно и измеряйте очередь/latency у LLM; больше параллельных запусков не делает один агентский шаг быстрее и часто снижает качество при rate limit.
- Полный экспорт намеренно включает `node_modules`, build-артефакты и кэши, так как это экспорт **всех** файлов. На очень больших рабочих областях он может быть долгим и требовать свободного места рядом с проектом. Для регулярного бэкапа кода предпочтительнее git push или компактный server-side export с исключениями.
- Не запускайте одновременно host-шлюз сервисов и проброс портов `8290–8300` из Docker: это приводит к `EADDRINUSE`. Базовый compose уже оставляет эти порты непроброшенными.
- Периодически проверяйте размер `projects/` и Docker volume `openhands_data`; ротация логов уже включена в `docker-compose.prod.yml`.
