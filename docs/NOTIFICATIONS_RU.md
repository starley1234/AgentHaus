# Уведомления: как агент отправляет отчёты на почту и в Telegram

AgentHaus умеет отправлять сообщения во внешний мир через навык **`notify`**
(`extensions/skills/notify`): письма по SMTP, сообщения в Telegram и в вебхуки
Slack/Discord/Mattermost.

Главная фишка: ты вводишь **ящик агента, профиль агента и свои контакты** один
раз в `.env` — и дальше достаточно сказать агенту «отправь мне отчёт на
почту», «напиши клиенту» или «зарегистрируйся на сайте». Агент возьмёт
получателя из настроек, а представляться будет одинаково по синтезированному
профилю — **не путая свою почту с почтой владельца**.

## Быстрый старт

1. Открой `.env` в корне проекта (если его нет — `cp .env.example .env`).
2. Заполни блок «Уведомления» **и профиль агента** (`AGENT_PROFILE_*`).
   Достаточно одного канала (email). Ящик агента должен быть отдельным от
   личной почты владельца.
3. Примени: при первом включении — `docker compose up -d --build` (в образ
   попадают навык и глобальная команда `notify`); дальше при смене значений
   в `.env` достаточно перезапуска `docker compose up -d`.
4. Скажи агенту: «отправь мне тестовое письмо» — он выполнит одну команду
   `notify email --subject "Тест" --body "…"` и адрес возьмёт из
   `NOTIFY_EMAIL_TO`, ничего не переспрашивая. Проверить, как агент
   представляется: `notify profile`.

## Канал 1: Email (SMTP)

Почтовый ящик (`SMTP_USER`) — **почта агента**, а не владельца. Агент:
- отправляет отчёты **владельцу** на `NOTIFY_EMAIL_TO`;
- пишет **третьим лицам** (`notify email --to …`);
- **регистрируется на сайтах** от своего имени: подставляет `AGENT_PROFILE_EMAIL`
  как адрес регистрации и принимает подтверждения в этом же ящике.

```ini
# ── Ящик агента (SMTP/IMAP) ──
SMTP_HOST=smtp.timeweb.ru
SMTP_PORT=465
SMTP_USER=agent@agent-domain.ru          # ← почта АГЕНТА
SMTP_PASSWORD=пароль-приложения
SMTP_FROM=                               # необязательно, по умолчанию = SMTP_USER

# ── Синтезированный профиль агента ──
AGENT_PROFILE_NAME=Ассистент AgentHaus   # имя для From и регистраций
AGENT_PROFILE_EMAIL=agent@agent-domain.ru # email агента для регистраций (= SMTP_USER)
AGENT_PROFILE_ROLE=Автономный ассистент   # как представляться третьим лицам
AGENT_PROFILE_SIGNATURE=--\nАссистент AgentHaus  # подпись в письмах (\n = перевод строки)

# ── Получатель-владелец ──
NOTIFY_EMAIL_TO=owner@yandex.ru          # ← ТВОЙ адрес: сюда уходят отчёты «отправь мне»
```

Смотри профиль одной командой (и для человека, и для агента):

```bash
notify profile          # имя, email, роль, подпись
notify profile --json   # то же в JSON — удобно для заполнения форм регистрации
```

⚠️ Для всех крупных провайдеров нужен **пароль приложения**, а не обычный
пароль от почты:

| Провайдер | SMTP_HOST | Порт | Где взять пароль приложения |
|---|---|---|---|
| Gmail | `smtp.gmail.com` | 587 | myaccount.google.com/apppasswords (нужна включённая 2FA) |
| Yandex | `smtp.yandex.ru` | 465 | id.yandex.ru → Безопасность → «Пароли приложений» (включи IMAP/SMTP в настройках Почты) |
| Mail.ru | `smtp.mail.ru` | 465 | account.mail.ru → Безопасность → «Пароли для внешних приложений» |
| Timeweb | `smtp.timeweb.ru` | 465 | обычный пароль от почтового ящика (паролей приложений нет) |
| Свой сервер | — | 465/587/25 | при необходимости задай `SMTP_SECURITY=ssl\|starttls\|none` |

Порт 465 = SSL, 587 = STARTTLS — скрипт определяет режим по порту сам.

## Приём писем и переписка (IMAP)

Агент умеет не только отправлять, но и **читать почту и отвечать** — вести
реальную переписку:

```bash
notify inbox --unseen        # непрочитанные письма (UID, дата, от кого, тема)
notify read --uid 42         # текст письма; --save-attachments DIR — вложения
notify reply --uid 42 --body "Ответ"   # ответ отправителю той же цепочкой (Re:)
```

Настройка почти всегда **не нужна**: если `SMTP_HOST` имеет вид
`smtp.<домен>`, IMAP-хост выводится автоматически (`imap.<домен>`, порт 993
SSL), а логин/пароль берутся из `SMTP_USER`/`SMTP_PASSWORD`.

Проверенные параметры провайдеров приёма:

| Провайдер | IMAP (SSL) | POP3 (SSL) |
|---|---|---|
| Timeweb | `imap.timeweb.ru:993` | `pop3.timeweb.ru:995` |
| Yandex | `imap.yandex.ru:993` | `pop.yandex.ru:995` |
| Gmail | `imap.gmail.com:993` (включи IMAP в настройках) | `pop.gmail.com:995` |
| Mail.ru | `imap.mail.ru:993` | `pop.mail.ru:995` |

Скрипт использует IMAP (письма остаются на сервере, видны флаги
прочитанности). Если хосты нестандартные — задай `IMAP_HOST`, `IMAP_PORT`,
`IMAP_USER`, `IMAP_PASSWORD` в `.env`.

**Отправленные сохраняются на сервере**: после успешной отправки копия
письма кладётся в папку «Отправленные» по IMAP (папка находится
автоматически по атрибуту `\Sent`; нестандартное имя — задай в
`IMAP_SENT_FOLDER`). Отключение: `NOTIFY_SAVE_SENT=0`. Ошибка сохранения
не считается ошибкой отправки — письмо всё равно ушло.

Типовые сценарии в диалоге:
- «проверь почту» → агент покажет непрочитанные из **своего** ящика;
- «прочитай письмо от Иванова и сделай, что он просит» → `read` → работа → `reply`;
- «отправь счёт клиенту» → `notify email --to …`, From = профиль агента;
- «зарегистрируйся на сайте» → `notify profile` → заполнить форму данными
  агента → `notify inbox --unseen` → `notify read` → подтвердить регистрацию;
- «следи за почтой и отвечай» → лучше оформить автоматизацией (cron-опрос
  `notify inbox --unseen`), а не бесконечным диалогом.

⚠️ Ящик агента должен быть **отдельным от личной почты** (например
`agent@твой-домен.ru` на том же Timeweb): у агента полный доступ к его
содержимому, и это нормально только для служебного адреса. Личную почту
владельца используй только как адрес получателя (`NOTIFY_EMAIL_TO`), а не как
ящик агента.

## Канал 2: Telegram

1. Напиши боту [@BotFather](https://t.me/BotFather) команду `/newbot`,
   получи токен вида `123456789:AA...` и внеси его в `.env`
   (`TELEGRAM_BOT_TOKEN=...`), перезапусти контейнер.
2. Найди своего нового бота по @username в поиске Telegram и отправь ему
   `/start` (без этого бот не сможет писать тебе — «chat not found»,
   а `getUpdates` будет пустым: `{"ok":true,"result":[]}`).
3. Узнай свой `chat_id` — попроси агента выполнить:
   ```bash
   notify chatid
   ```
   Команда сама проверит типовые проблемы: бот без сообщений (подскажет
   написать `/start`; учти, что обновления хранятся ~24 часа), установленный
   webhook (снимается `notify chatid --delete-webhook`), и при успехе
   напечатает готовую строку `TELEGRAM_CHAT_ID=...` для `.env`.
   Альтернатива вручную: открой в браузере
   `https://api.telegram.org/bot<ТОКЕН>/getUpdates` **сразу после** сообщения
   боту и найди `"chat":{"id":123456789,...}`.
4. Заполни `.env`:

```ini
TELEGRAM_BOT_TOKEN=123456789:AA...
TELEGRAM_CHAT_ID=123456789
```

Длинные отчёты автоматически режутся на сообщения по ~4000 символов; файлы
агент может прислать документом.

## Канал 3: Вебхук (Slack / Discord / Mattermost)

```ini
NOTIFY_WEBHOOK_URL=https://hooks.slack.com/services/...
```

Discord-вебхуки распознаются по URL автоматически (используется поле
`content` и отключаются пинги `@everyone`). URL вебхука — это секрет,
не публикуй его.

## Как это устроено

```
.env  →  docker-compose.yml (environment)  →  agent-server в контейнере
                                                  │ (наследование env)
                                                  ▼
                              bash-инструмент агента → команда `notify`
                              (обёртка в /usr/local/bin →
                               extensions/skills/notify/scripts/notify.py)
```

- В Docker-образе есть глобальная команда **`notify`** — агенту не нужно
  искать скрипт по файловой системе, отправка = один вызов.
- Навык `notify` зарегистрирован в вендоренном каталоге
  (`extensions/marketplaces/openhands-extensions.json`), агент подхватывает
  его автоматически — по триггерам «отправь на почту», «в телеграм»,
  «уведоми меня» и т.п.
- `notify.py` — чистый stdlib Python, без установки зависимостей.
- Команды: `status`, `email`, `telegram`, `webhook`, `send` (во все каналы).

## Безопасность

- `.env` уже в `.gitignore` — пароли в git не попадут.
- Навык запрещает агенту выводить `SMTP_PASSWORD`, `TELEGRAM_BOT_TOKEN` и
  URL вебхука в чат/логи; скрипт дополнительно маскирует их в ошибках.
- Агент отправляет письма только на адрес из настроек или на адрес, который
  ты явно назвал; массовые рассылки запрещены инструкцией навыка.

## `.env` или «Секреты» в интерфейсе — где хранить настройки?

В Canvas есть функционал **Settings → Секреты** («именованные значения,
которые агент может использовать во время диалогов»). Разбор, что куда
класть.

**Как работают Секреты технически** (SDK, `SecretRegistry`): значения
хранятся зашифрованными ключом `OH_SECRET_KEY` и **впрыскиваются в окружение
bash-команды только тогда, когда текст команды упоминает имя секрета**
(например, команда содержит строку `SMTP_PASSWORD`). Дополнительный бонус —
значения секретов автоматически **маскируются в выводе команд** и логах
диалога.

**Как работает `.env`**: переменные через docker-compose попадают в окружение
agent-server и наследуются каждой bash-командой агента — всегда, без условий.
Команда `notify email …` не содержит слов `SMTP_PASSWORD`, поэтому она
работает именно благодаря этому пути.

| Критерий | `.env` | Секреты (UI) |
|---|---|---|
| Шифрование при хранении | нет (plaintext-файл на хосте) | да (Fernet, `OH_SECRET_KEY`) |
| Маскирование в выводе/логах диалога | нет (полагаемся на дисциплину навыка) | да, автоматическое |
| Попадает в окружение | всегда, любой команде | только если команда упоминает имя секрета |
| Работает с `notify email …` «как есть» | ✅ | ❌ (команда не упоминает имён секретов) |
| Изменение без перезапуска контейнера | ❌ (нужен `docker compose up -d`) | ✅ (сразу из UI) |
| Доступно сервисам вне диалога (gateway, автоматизации) | ✅ | ❌ (только внутри диалогов) |

**Рекомендация:**
- **Несекретное** (`SMTP_HOST`, `SMTP_PORT`, `SMTP_USER` — ящик агента,
  `AGENT_PROFILE_*`, `IMAP_HOST`, `NOTIFY_EMAIL_TO`, `TELEGRAM_CHAT_ID`) —
  однозначно `.env`: это конфигурация, а не тайна.
- **Секретное** (`SMTP_PASSWORD`, `TELEGRAM_BOT_TOKEN`, `NOTIFY_WEBHOOK_URL`)
  — сейчас практичнее тоже `.env` (self-hosted инстанс, файл и так у тебя на
  хосте; главное — не коммитить). Перенос в Секреты даст шифрование и
  автоматическое маскирование, но потребует доработки: либо навык должен
  явно упоминать имена секретов в командах (например
  `SMTP_PASSWORD="$SMTP_PASSWORD" notify email …`), либо обёртка `notify`
  должна уметь запрашивать секреты. Это осознанный кандидат на следующую
  итерацию — код при этом менять придётся минимально (одна строка в SKILL.md).
- **Гибрид** (лучшее из обоих, когда понадобится): конфигурация в `.env`,
  пароли в Секретах с теми же именами — приоритет у значения из окружения
  команды.

- Вложения и содержимое писем: агент читает ящик целиком — для переписки
  заведи отдельный служебный адрес, а не личную почту.

## Типичные проблемы

| Симптом | Решение |
|---|---|
| «email не настроен» | заполни SMTP_HOST/SMTP_USER/SMTP_PASSWORD в `.env`, перезапусти контейнер |
| SMTP-аутентификация не прошла | используй пароль приложения (см. таблицу выше) |
| Telegram «chat not found» | отправь боту `/start`; проверь `TELEGRAM_CHAT_ID` |
| Письма уходят в спам | заполни `SMTP_FROM` тем же адресом, что `SMTP_USER` |
| Таймаут SMTP | проверь порт/файрвол; попробуй 587 + `SMTP_SECURITY=starttls` |
| IMAP не подключается | проверь `IMAP_HOST` (Timeweb: `imap.timeweb.ru`, порт 993 SSL); логин = полный адрес ящика |
| Telegram не отправляет из РФ-сети | проверь доступ к api.telegram.org; при необходимости задай HTTP_PROXY в `.env` (скрипт его учитывает) |
