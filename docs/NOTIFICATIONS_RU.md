# Уведомления: как агент отправляет отчёты на почту и в Telegram

AgentHaus умеет отправлять сообщения во внешний мир через навык **`notify`**
(`extensions/skills/notify`): письма по SMTP, сообщения в Telegram и в вебхуки
Slack/Discord/Mattermost.

Главная фишка: ты вводишь свои контакты **один раз** в `.env` — и дальше
достаточно сказать агенту «отправь мне отчёт на почту» или «уведоми меня в
телеграме, когда закончишь». Агент возьмёт получателя из настроек и **не будет
задавать уточняющих вопросов**.

## Быстрый старт

1. Открой `.env` в корне проекта (если его нет — `cp .env.example .env`).
2. Заполни блок «Уведомления» (достаточно одного канала).
3. Перезапусти контейнер: `docker compose up -d` (при уже собранном образе
   пересборка не нужна — переменные подхватятся при рестарте).
4. Проверь в диалоге с агентом: «проверь, какие каналы уведомлений настроены»
   (агент выполнит `notify.py status`), затем — «отправь мне тестовое письмо».

## Канал 1: Email (SMTP)

```ini
SMTP_HOST=smtp.yandex.ru
SMTP_PORT=465
SMTP_USER=me@yandex.ru
SMTP_PASSWORD=пароль-приложения
SMTP_FROM=            # необязательно, по умолчанию = SMTP_USER
NOTIFY_EMAIL_TO=me@yandex.ru   # ← ТВОЙ адрес: сюда уходят отчёты «отправь мне»
```

⚠️ Для всех крупных провайдеров нужен **пароль приложения**, а не обычный
пароль от почты:

| Провайдер | SMTP_HOST | Порт | Где взять пароль приложения |
|---|---|---|---|
| Gmail | `smtp.gmail.com` | 587 | myaccount.google.com/apppasswords (нужна включённая 2FA) |
| Yandex | `smtp.yandex.ru` | 465 | id.yandex.ru → Безопасность → «Пароли приложений» (включи IMAP/SMTP в настройках Почты) |
| Mail.ru | `smtp.mail.ru` | 465 | account.mail.ru → Безопасность → «Пароли для внешних приложений» |
| Свой сервер | — | 465/587/25 | при необходимости задай `SMTP_SECURITY=ssl\|starttls\|none` |

Порт 465 = SSL, 587 = STARTTLS — скрипт определяет режим по порту сам.

## Канал 2: Telegram

1. Напиши боту [@BotFather](https://t.me/BotFather) команду `/newbot`,
   получи токен вида `123456789:AA...`.
2. Найди своего нового бота в Telegram и отправь ему `/start`
   (без этого бот не сможет писать тебе — «chat not found»).
3. Узнай свой `chat_id`: открой в браузере
   `https://api.telegram.org/bot<ТОКЕН>/getUpdates`
   и найди `"chat":{"id":123456789,...}`.
4. Заполни `.env`:

```ini
TELEGRAM_BOT_TOKEN=123456789:AA...
TELEGRAM_CHAT_ID=123456789
```

Длинные отчёты автоматически режутся на сообщения по ~4000 символов; файлы
агент может прислать документом.

## Канал 3: Вебхук (Slack / Discord / Mattermost)

```ini
NOTIFY_WEBHOOK_URL=https://hooks.slack.com/services/...
```

Discord-вебхуки распознаются по URL автоматически (используется поле
`content` и отключаются пинги `@everyone`). URL вебхука — это секрет,
не публикуй его.

## Как это устроено

```
.env  →  docker-compose.yml (environment)  →  agent-server в контейнере
                                                  │ (наследование env)
                                                  ▼
                              bash-инструмент агента → notify.py
                              (extensions/skills/notify/scripts/notify.py)
```

- Навык `notify` зарегистрирован в вендоренном каталоге
  (`extensions/marketplaces/openhands-extensions.json`), агент подхватывает
  его автоматически — по триггерам «отправь на почту», «в телеграм»,
  «уведоми меня» и т.п.
- `notify.py` — чистый stdlib Python, без установки зависимостей.
- Команды: `status`, `email`, `telegram`, `webhook`, `send` (во все каналы).

## Безопасность

- `.env` уже в `.gitignore` — пароли в git не попадут.
- Навык запрещает агенту выводить `SMTP_PASSWORD`, `TELEGRAM_BOT_TOKEN` и
  URL вебхука в чат/логи; скрипт дополнительно маскирует их в ошибках.
- Агент отправляет письма только на адрес из настроек или на адрес, который
  ты явно назвал; массовые рассылки запрещены инструкцией навыка.
- Альтернатива `.env`: те же переменные можно завести как секреты в
  Settings → Secrets интерфейса Canvas — они тоже попадают в окружение агента.

## Типичные проблемы

| Симптом | Решение |
|---|---|
| «email не настроен» | заполни SMTP_HOST/SMTP_USER/SMTP_PASSWORD в `.env`, перезапусти контейнер |
| SMTP-аутентификация не прошла | используй пароль приложения (см. таблицу выше) |
| Telegram «chat not found» | отправь боту `/start`; проверь `TELEGRAM_CHAT_ID` |
| Письма уходят в спам | заполни `SMTP_FROM` тем же адресом, что `SMTP_USER` |
| Таймаут SMTP | проверь порт/файрвол; попробуй 587 + `SMTP_SECURITY=starttls` |
