# Управление историей диалогов и токенами

## Что уже есть

AgentHaus уже получает от agent-server агрегированные `metrics.accumulated_token_usage`: входные (`prompt_tokens`), выходные (`completion_tokens`), cache read/write, окно контекста и стоимость. Поэтому хранить копию каждого события в собственной БД для простой аналитики не требуется. Новая страница **Настройки → Управление диалогами** показывает эти агрегаты, умеет искать диалоги, выбирать несколько, удалять и экспортировать метаданные в JSON.

## Рекомендуемая политика хранения

1. **Всегда хранить агрегат на уровне диалога**: `input_tokens`, `output_tokens`, `cache_read_tokens`, `cache_write_tokens`, `total_cost`, `last_activity_at`, `message_count`. Обновлять его идемпотентно после каждого ответа или фоновой синхронизацией.
2. **Подробные события** держать 24 часа (настраиваемый TTL). После TTL удалять текст событий и payload инструментов, оставляя агрегат и короткое название/резюме. Не удалять активные диалоги и архивы автоматически.
3. Перед удалением подробностей выполнять фоновую задачу с пакетами и индексом по `created_at`; не делать массовый `DELETE` в HTTP-запросе. Нужны retry, dry-run и журнал результата.
4. Для экспорта дать два режима: JSON/Markdown с текстом и облегчённый CSV/JSON только с метриками. Перед удалением предложить экспорт. Секреты, API-ключи и session keys никогда не включать в экспорт.
5. Для SQLite — индексы `(updated_at)`, `(created_at)`, `(execution_status)` и `(archived_at)`; для PostgreSQL — те же индексы плюс ограничение размера payload и отдельное объектное хранилище для больших траекторий.

## Что следует улучшить дальше

- Добавить серверные `PATCH archive/unarchive` и `POST bulk` с проверкой владельца, CSRF/auth и защитой от удаления активного запуска.
- Реализовать настоящую архивацию: архив скрывается из обычного списка, но остаётся доступен для чтения и восстановления. Текущий статус sandbox `MISSING` не должен использоваться как синоним пользовательского архива.
- Сделать пагинацию/виртуализацию списка (сейчас UI загружает до 100 записей), фильтры по статусу, диапазону дат, модели, репозиторию, наличию ошибок и диапазону токенов.
- Для массовых операций добавить подтверждение с количеством, progress, отмену, частичный успех и аудит.
- Синхронизировать очистку client-side metadata/localStorage при удалении и добавить тесты для API, TTL, фильтрации и bulk-операций.
- Показывать в карточке диалога контекст: вход/выход, cache hit, стоимость, долю окна контекста и предупреждение при приближении к лимиту.
- Не считать токены по длине строки как источник истины: использовать usage от провайдера, а локальную оценку явно помечать как приблизительную.

## Ограничения текущего MVP

Экспорт страницы сохраняет метаданные и агрегированные метрики, а не полную траекторию. Полный экспорт конкретного диалога уже доступен в самом диалоге; объединение нескольких бинарных trajectory-файлов в один ZIP следует добавить на сервере, чтобы не держать большие файлы в памяти браузера.
