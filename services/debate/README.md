# Сервис «debate» — разговор агентов на заданную тему

Управляемая дискуссия 2–3 агентов (каждый — **отдельный диалог** на едином
бэкенде, по своему агент-профилю) на заданную тему. Опционально арбитр
подводит вердикт. Итог — **сайт-стенограмма**.

## Возможности

- **Отдельные профили-диалоги**: каждый агент создаётся как самостоятельный
  диалог на едином бэкенде (используются существующие профили/LLM).
- **N раундов** — сколько кругов обсуждения провести.
- **Ограничение контекста** — между агентами передаётся только **скользящее
  окно** последних реплик (`window_size`), а не вся история.
- **Режим суммаризации** (`summarize`) — после каждого раунда предыдущий
  сворачивается в краткое резюме (отдельный суммаризатор), которое передаётся
  дальше; контекст не раздувается.
- **Арбитр (опционально)** — отдельный агент, который в конце даёт вердикт
  (ключевые аргументы, согласованные пункты, разногласия).
- **Сайт-стенограмма** — полная запись дискуссии, публикуется по HTTP.

## Запуск

```bash
cd services/debate
AGENT_SERVER_URL=http://localhost:8000 AGENT_SERVER_API_KEY=<key> node server.mjs
```

Открыть: http://localhost:8293/

## API

| Маршрут | Описание |
| --- | --- |
| `POST /api/run` | `{ topic, agents:[{name,profile?}], rounds, window_size, summarize, with_arbiter }` → `{ jobId }` |
| `GET  /api/status?id=` | статус (running / finished / error), кол-во реплик |
| `GET  /api/result?id=` | итог: transcript, summary, arbiter, ссылку на сайт |
| `GET  /site/<jobId>/` | сайт-стенограмма |

## Настройка (config.json)

- `defaults.rounds`, `defaults.window_size`, `defaults.summarize` — параметры по умолчанию;
- `arbiter.profile_name` / `system_prompt` — арбитр;
- `agent_system_prompt` — общий промпт участника (можно доопределять в `agent_system_prompt`).

## Как это не ломает ядро

Используются только стандартные REST-эндпоинты agent-server (создание диалога,
отправка сообщения `POST .../events`, финальный ответ). Всё новое — аддитивный
слой (сервис-прослойка), ядро SDK не изменяется.
